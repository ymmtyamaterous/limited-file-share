# 全体概要仕様書

## 1. プロジェクト概要

**サービス名:** Limited File Share  
**目的:** ファイルおよびテキストを手軽に共有できる一時的なファイル共有サービス  
**特徴:** アカウント登録不要、パスキー保護、有効期限付き自動削除

---

## 2. 機能一覧

### 2.1 コア機能

| 機能 | 説明 | 優先度 |
|------|------|--------|
| ファイルアップロード | 各種ファイルをアップロードして共有URLを生成する | 必須 |
| テキスト共有 | テキスト/コードスニペットを直接入力して共有する | 必須 |
| パスキー設定 | 共有コンテンツにアクセスパスワードを設定する | 必須 |
| 有効期限設定 | コンテンツに保存期間（有効期限）を設定する | 必須 |
| 共有URLアクセス | 共有URLとパスキーでコンテンツにアクセスする | 必須 |
| ファイルダウンロード | 共有されたファイルをダウンロードする | 必須 |
| 自動削除 | 有効期限を過ぎたコンテンツを自動的に削除する | 必須 |

### 2.2 追加機能

| 機能 | 説明 | 優先度 |
|------|------|--------|
| テキストプレビュー | テキスト・コードのインラインプレビュー表示 | 高 |
| 画像プレビュー | 画像ファイルのインラインプレビュー表示 | 高 |
| 共有リンクコピー | ワンクリックで共有URLをクリップボードにコピー | 高 |
| QRコード生成 | 共有URLのQRコードを表示する | 中 |
| ダウンロード回数制限 | ダウンロード可能な最大回数を設定できる | 中 |
| コンテンツ削除 | 作成者が手動でコンテンツを削除できる（削除トークン使用） | 高 |
| ファイルサイズ制限 | 1ファイルあたり最大50MBまでのアップロード制限 | 必須 |
| 複数ファイルアップロード | 1回の操作で複数ファイルをアップロード | 低 |

## 3. 非機能要件

### 3.1 セキュリティ

- パスキーはサーバー側でハッシュ化して保存する（bcrypt）
- 共有IDはランダムな短縮URLとして生成（UUIDv4 の先頭8文字など）
- 削除トークンは作成時のみ発行し、再表示不可
- ファイルのMIMEタイプを検証し、悪意あるファイルのアップロードを制限
- レートリミット: 同一IPからの短時間での大量アップロードを制限

### 3.2 パフォーマンス

- ファイルアップロード: 最大 50MB
- 対応有効期限: 1時間 / 1日 / 7日 / 30日
- テキストコンテンツ: 最大 1MB

### 3.3 可用性・運用

- 定期的なクリーンアップジョブで期限切れコンテンツを削除
- クリーンアップ間隔: 1時間ごと（cronジョブ相当）

## 5. システム構成

```
[ユーザーブラウザ]
      │
      │ HTTPS
      ▼
[Webフロントエンド: React + TanStack Router]
      │
      │ oRPC / REST
      ▼
[バックエンドAPI: Hono on Bun]
      │
      ├─ 認証: better-auth
      ├─ ファイルストレージ: ローカルファイルシステム
      └─ データベース: SQLite (Drizzle ORM)
```

## 6. ユーザーフロー

### 6.1 コンテンツ共有フロー

```
[共有者]
  1. トップページにアクセス
  2. ファイルまたはテキストを選択・入力
  3. パスキーを設定
  4. 有効期限を選択
  5. 「共有」ボタンを押す
  6. 共有URLと削除トークンが表示される
  7. URLをコピーして相手に送信
```

### 6.2 コンテンツアクセスフロー

```
[受信者]
  1. 共有URLにアクセス
  2. パスキー入力フォームが表示される
  3. パスキーを入力して認証
  4. コンテンツ（テキスト or ファイル）が表示される
  5. ファイルの場合はダウンロード、テキストの場合はコピーも可能
```

### 6.3 コンテンツ削除フロー

```
[共有者]
  1. 削除トークンを用いて削除APIを呼び出す
  2. コンテンツが即座に削除される
```

---

## 7. 制約事項

- アカウント登録は不要（管理者向けにのみ better-auth を利用）
- パスキーを忘れた場合のリカバリ手段は提供しない
- ファイルストレージはサーバーのローカルファイルシステムを使用（初期実装）
- アップロード可能なファイルタイプは制限なし（ウイルススキャンは対象外）
